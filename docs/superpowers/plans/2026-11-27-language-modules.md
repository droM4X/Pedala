# Language Modules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add drop-in language modules to Pedala: English stays the source, `lang/<code>.js` is the whole language, missing file/key falls back to English, and no per-language `if` exists in the core.

**Architecture:** `i18n.js` is a classic script (UMD-exported for Node tests) that owns the registry, text/plural/date/number helpers, the one-time static DOM pass, the module loader and the English speech defaults. `lang/<code>.js` self-registers via `PedalaI18n.add({...})`. A static `lang/index.json` (generated by `scripts/langs.js`) lists available languages; the app also tries the browser language directly. The app wraps its existing init in `PedalaI18n.init(settings.lang)` and converts dynamic strings to explicit `t()` calls.

**Tech Stack:** Vanilla JS (classic scripts, zero build), Node 20 for tests and the manifest generator, Playwright/Chromium for e2e, Vercel static hosting + middleware.

**Spec:** `docs/superpowers/specs/2026-11-27-language-modules-design.md` — read it first; this plan argues from it.

## Global Constraints

- Zero build: no bundler, no new runtime dependency. `scripts/langs.js` uses only Node built-ins (`fs`, `path`, `vm`, `crypto`).
- English text in `index.html` and inline JS is the source of truth and the message key. Do not re-key strings.
- No per-language `if`/`switch` in `i18n.js` or `index.html`. Language-specific grammar lives in the module.
- With no language file the app must behave exactly as today (English), including dates, numbers, plurals and voice strings.
- Language files are classic scripts loaded after login; no server discovery endpoint.
- User data (video titles, imported ZWO/GPX names/descriptions, coach output, user notes) is never passed to `t()`.
- `settings.lang` is per device: add it to `SYNC_SKIP`, not to the synced payload.
- Stale `uiLang`/`voiceLang` in existing `localStorage` stays ignored.
- Existing English tests keep passing, except deliberate plural fixes (`1 kilometer`, `1 second`), which update their pinned assertions.
- Commit after every task.

## Review Focus

1. **Missing/stale/unknown language:** `settings.lang = "xx"`, a deleted `lang/xx.js`, or a stale `index.json` must boot English with no page error and no blank language select.
2. **`i18n.js` failure or slow load:** the app must still boot. The inline English shim, always-resolving init and readiness flag are the safety net; never leave the app hidden or uninitialized.
3. **Static markup safety:** `[data-i18n]` is only on elements whose `innerHTML` can be replaced. A `<label>` wrapping an `<input>` must translate its text node or a `<span>`, or the control disappears.
4. **User content:** video titles, imported workout/route names, coach comments and user notes must render unchanged in every language.
5. **English unchanged:** dates, numbers, plurals and the pinned voice sentence stay byte-identical in English mode (`In 10 seconds: 3 minutes at 265 watts, cadence 90 to 100.`).

Each line gets a test in the task that owns the code.

- [ ] **Step 3: Implement `i18n.js`**

UMD wrapper `(function(root){ ... })(typeof window !== "undefined" ? window : globalThis)` with:

- Built-in English descriptor `{ code: "en", name: "English", locale: "en-GB", strings: {}, speech: englishSpeech }`.
- `add` validates minimal shape, stores in `languages`, returns the object.
- `use(code)` sets `active`, `code`, `locale` (default `code`), `dir` (default `ltr`), `speechLang` (default `code`), and returns false for unknown codes.
- `t`/`tHtml`: `const s = active.strings[key] ?? key; return s.replace(/\{(\w+)\}/g, (_, k) => vars?.[k] ?? `{${k}}`)`.
- `tn`: if `active.tn` use it; else select `active.plural?.(n) === "one" ? one : other`, then `t(selected, {...vars, n})`.
- `td`/`tnum`: if `active.date`/`active.number` use it; else cached `Intl.DateTimeFormat(active.locale, opts)` / `Intl.NumberFormat(active.locale, opts)`.
- `localizeDom`: one-time pass; guard `typeof document === "undefined"`; skip `SCRIPT/STYLE/CANVAS/NOSCRIPT` and `[data-i18n]` subtrees; text nodes exact trimmed match with whitespace preserved; attributes `placeholder`, `aria-label`, `title`, `alt`; `[data-i18n]` replaces `innerHTML`; record keys in `seen` when `record` is true.
- `englishSpeech`: the English builders, copied exactly from `index.html` `lapResult`/`watts`/`sayDur`/`cadSay`/`segSpeech`/`segSpeechPower`/`finishWorkout`/strength speech, with the agreed signatures (`watts(n)`, `duration(sec)`, `cadence(lo,hi,any)`, `segment(seg,ctx)`, `lap(lap,ctx)`, `finish(route)`, `strength(step,next)`, `start()`, `soon(segment)`).
- `speech` getter merges English with `active.speech` only when `speechLang === active.code`; otherwise English. `setSpeechLang(code)`.
- `init(pref)`/`load(code, version)`/`available()` per the spec; `init` always resolves, sets `document.documentElement.lang/dir`, runs `localizeDom`, and sets `dataset.i18n = "ready"` after the caller's init (the caller sets that flag; the core exposes `ready`).
- `record` + `seen` for the coverage tool.
